AI / Agent 体验指标
拆解字典

七维拆解 × 自进化循环 12 CORE METRICS · 7 DIMENSIONS EACH

指标的名字只是开始。一个指标只有回答了「为什么测、怎么算、多少算好、数据从哪来、怎么分层看、异常时谁被触发、改进后如何验证固化」这七个问题，才从一行报表数字，变成一台驱动体验自进化的发动机。

本字典是《AI 体验 / Agent 体验指标体系》的姊妹卷：沿用其面向大众体验设计师的指标命名，对 12 个核心指标（P0×6 + P1×6）逐一进行七维拆解，并把它们咬合成一个持续运转的改进闭环。

一
CHAPTER 01 · THE 7-DIMENSION MODEL

七维拆解模型

每个指标都按七个维度拆解。前四维让指标「可测量、可判断」，后三维让指标「可行动、可进化」——大多数指标体系死在前四维，活着靠后三维。

DIM 01
指标目的
PURPOSE

这个指标为什么存在？它回答体验的哪一个根本问题？谁需要看它？

DIM 02
公式与口径
FORMULA

分子分母的精确定义。口径不统一，两个团队会为同一个数字吵架。

DIM 03
评估标准
THRESHOLDS

多少算健康、多少算预警、多少算危险。没有阈值的数据只是装饰。

DIM 04
数据来源
DATA SOURCE

埋点、日志、评测集还是问卷？来源决定可信度，也决定成本。

DIM 05
分层方式
SEGMENTATION

按什么切分才能暴露真相：风险等级、任务难度、用户群体、时间窗。总量会撒谎，分层才诚实。

DIM 06
触发机制
TRIGGER

指标异常时，谁在什么条件下被触发做什么事。没有触发机制的指标，异常了也没人动。

DIM 07
改进闭环
CLOSED LOOP

从异常到归因、修复、验证、固化的完整路径。闭环的产物必须沉淀为资产，循环才算进化。

二
CHAPTER 02 · SELF-EVOLVING LOOP

六环自进化循环

七维拆解不是静态档案，而是一台循环机器：测量 → 触发 → 诊断 → 改进 → 验证 → 固化，每一圈都必须比上一圈更聪明——因为闭环沉淀下来的评测用例、设计规范与验收标准，会让下一轮的测量更准、诊断更快。

FLYWHEEL

指标驱动的体验自进化

MEASURE → TRIGGER → DIAGNOSE → FIX → VERIFY → SOLIDIFY

指标是循环的发动机

每个指标卡就是一个微型循环：阈值（DIM 03）决定何时触发，分层（DIM 05）决定如何诊断，闭环（DIM 07）决定改进去向。

沉淀是进化的前提

验证成功后必须沉淀资产：评测用例入库、设计规范更新、验收标准修订。不沉淀的循环只是原地打转。

指标自身也在被改进

循环每转一圈，回头审视指标本身：口径是否还准确？阈值是否还合身？失效的指标要下线，指标体系才能进化。

CHAPTER 03 · P0 METRICS

P0 核心指标拆解

P0 · 01

端到端任务成功率

END-TO-END TASK SUCCESS
M-01

端到端任务成功率

End-to-End Task Success Rate
目的PURPOSE
回答「用户委托的目标是否真正达成」——从目标输入到最终交付的全链路成功，而非单步成功。它是北极星「用户目标成功率」最直接的观测面，也是所有体验指标的锚点：其他指标异常时，最终都会反映在这里。
公式FORMULA
任务成功率=满足全部验收标准的任务数纳入评测的任务总数× 100%
口径：验收标准必须事前定义；部分完成、用户中途放弃、降级完成均不计入成功。
评估标准THRESHOLDS
≥ 85% 健康70–85% 预警< 70% 危险
阈值必须按任务难度分层设定：低风险标准化任务的基线应显著高于开放式复杂任务。跨难度直接比较是本指标最常见的滥用。
数据来源DATA
  • 行为日志：任务状态机终态（完成 / 失败 / 放弃 / 接管）
  • 客观评测：标准任务集的事前验收判定
  • 用户信号：显式验收动作（接受 / 重做 / 差评）
分层SEGMENTS
按任务风险等级（L0 只读 → L3 不可逆）、任务难度（步骤数 / 依赖工具数）、用户群体（新手 / 专家）、时间窗（周 / 月）四个轴切分。
触发TRIGGER
⚡周环比下降 > 5pp → 触发一级诊断，48 小时内归因报告
⚡任一高风险任务层跌破危险线 → 立即触发专项复盘，相关功能降级评估
闭环CLOSED LOOP
失败任务聚类 → 四类归因（理解错 / 执行错 / 工具失败 / 环境异常）→ 分发给对应责任方修复 → A/B 实验验证 → 沉淀：失败样本转化为新评测用例，进入回归集。
M-02

结果可用率

Usable Output Rate
目的PURPOSE
区分「生成了」与「能用」。回答「用户拿到结果后，能否直接投入使用」——防止用生成量、字数、代码行数制造繁荣假象。
公式FORMULA
结果可用率=无需重大修改即可使用的输出数总输出数× 100%
口径：「重大修改」= 用户改动超过输出量 30%，或改动核心结构 / 逻辑。微调措辞不算。
评估标准THRESHOLDS
≥ 85% 健康70–85% 预警< 70% 危险
数据来源DATA
  • 行为日志：用户编辑 diff（改动体量与位置）
  • 显式反馈：「可直接使用 / 需修改」一键评价
  • 抽样评审：每周随机抽样人工判定校准
分层SEGMENTS
按输出类型（代码 / 文案 / 图表 / 文档）、输出长度、任务类型切分——不同类型输出的可用率不可混算。
触发TRIGGER
⚡某类输出可用率连续两周低于基线 10pp → 触发该类型的提示词 / 模型 / 模板专项优化
⚡用户 diff 中「结构性改动」占比上升 → 触发输出格式与结构评审
闭环CLOSED LOOP
不可用样本归因（格式错 / 内容错 / 风格偏）→ 对症优化对应环节 → 观察 diff 体量下降 → 沉淀：典型失败输出入库为负例，用于评估集与 few-shot 校准。
M-03

目标对齐率

Goal Alignment Rate
目的PURPOSE
回答「AI 做的是不是用户想的那件事」。防止「做得漂亮，但不是我要的」——这是 AI 产品最隐蔽的体验杀手：技术成功、任务失败。
公式FORMULA
目标对齐率=最终行为符合用户目标的任务数总任务数× 100%
口径：用户目标需在任务开始时登记（显式或推断）；符合性由事后判定或用户确认得出。
评估标准THRESHOLDS
≥ 88% 健康75–88% 预警< 75% 危险
与「意图漂移率」联动解读：起始对齐但中途漂移，是长程任务专属病灶。
数据来源DATA
  • 任务目标登记字段（用户输入 / 澄清后确认）
  • 执行路径日志与最终产物比对
  • 用户纠错与重定向信号
分层SEGMENTS
按目标明确度（显式给定 / 隐含推断）、任务跨度（单轮 / 多步骤）、领域切分。隐含目标的失败率天然更高，应单列基线。
触发TRIGGER
⚡隐含目标任务失败率 ≥ 显式目标 2 倍 → 触发澄清机制优化（何时追问、怎么追问）
⚡长任务漂移率上升 → 触发目标锚定设计（计划展示 / 关键节点复核）
闭环CLOSED LOOP
漂移样本分析 → 优化澄清策略 / 计划确认点 → 验证对齐率回升 → 沉淀：高频目标模式固化为领域模板与预设澄清问题库。
M-04

安全违规率

Safety Violation Rate
目的PURPOSE
红线指标。回答「是否存在不可接受的风险」。不参与任何加权与抵消——高满意度、高成功率都无法为安全违规背书。它定义了体验的下限。
公式FORMULA
安全违规率=违反安全政策 / 权限 / 关键约束的任务数总任务数× 100%
口径：按严重度三级记账——高危（不可逆损失 / 越权资金操作）、中危（权限越界未造成损失）、低危（策略边缘行为）。
评估标准THRESHOLDS
目标值 = 0高危：立即冻结中危：24h 复盘低危：周内修复
任何非零读数都触发响应，区别只在响应速度与升级层级。
数据来源DATA
  • 权限系统与操作审计日志
  • 内容安全审核流水
  • 红队测试集（定期主动攻击）
分层SEGMENTS
按严重度、场景风险等级、违规类型（权限 / 内容 / 隐私 / 资金）切分。不同类型走不同的响应通道。
触发TRIGGER
⚡任一高危违规 → 自动冻结相关授权扩张 + 值班响应 + 管理层通报
⚡中低危 → 周安全复盘会固定议程
闭环CLOSED LOOP
违规样本根因分析（策略缺失 / 模型越权 / 工具漏洞）→ 补策略 / 加护栏 / 收紧权限模型 → 红队回归测试 → 沉淀：安全基线与红线清单更新，违规样本进入对抗测试集。
M-05

用户纠错成功率

User Correction Success Rate
目的PURPOSE
回答「用户能否有效纠正 AI」。可控性体验的核心：AI 会犯错不可怕，用户纠不动才可怕——「失控感」正是用户不敢委托的根源。
公式FORMULA
纠错成功率=纠正后达到预期结果的次数有效纠错尝试总次数× 100%
口径：「有效纠错尝试」= 用户发出明确修正意图的动作（重新生成 / 补充说明 / 否定反馈 / 手动接管）。
评估标准THRESHOLDS
≥ 80% 健康65–80% 预警< 65% 危险
低于 65% 意味着用户「说了也没用」——是流失的最强前导信号之一。
数据来源DATA
  • 纠错动作日志（类型 / 轮次 / 内容）
  • 纠错后的任务终态追踪
  • 否定反馈按钮与重生成事件
分层SEGMENTS
按纠错类型（重试 / 补充说明 / 接管 / 放弃）与纠错轮次切分。连续纠错 3 轮以上的会话单列——它们是挫败感的重灾区。
触发TRIGGER
⚡同一会话同类纠错连续失败 2 次 → 触发升级人工通道 / 换策略建议
⚡整体跌破健康线 → 触发纠错交互（反馈控件 / 修正表达方式）优化专项
闭环CLOSED LOOP
失败纠错样本 → 诊断纠错接口缺失（用户无法精准表达哪里错）→ 增加针对性反馈控件 / 修正建议 → 验证成功率 → 沉淀：高频纠错模式入库，反哺默认行为设计。
M-06

异常恢复率

Failure Recovery Rate
目的PURPOSE
回答「失败后能否回到正轨」。系统成熟度的试金石：首次成功率靠运气也可能高，恢复率只能靠工程与设计能力。
公式FORMULA
异常恢复率=出错后恢复并最终完成的任务数出现错误的任务数× 100%
配套口径：平均恢复时间 MTTR = 从失败发生到任务回到正轨的平均时长。
评估标准THRESHOLDS
≥ 70% 健康50–70% 预警< 50% 危险
同时约束 MTTR < 2 × 同类任务正常完成时间，两者任一超标都算预警。
数据来源DATA
  • 错误事件日志（类型 / 时点 / 上下文）
  • 恢复路径追踪（自主恢复 / 用户介入 / 放弃）
  • 断点保存与续跑记录
分层SEGMENTS
按错误类型（工具失败 / 网络 / 模型拒绝 / 状态丢失）、发生时点（任务早期 / 中期 / 后期）切分——后期失败的恢复价值远高于早期，用户承受的沉没成本更大。
触发TRIGGER
⚡MTTR 超过正常完成时间 2 倍 → 触发恢复机制专项（「错了不如重做」是体验灾难）
⚡同一错误重复率 > 20% → 触发根因修复而非继续打补丁
闭环CLOSED LOOP
恢复失败样本 → 补断点保存 / 重试策略 / 回滚机制 → 混沌注入测试验证 → 沉淀：错误处理手册更新，错误模式进入故障演练库。

P1 核心指标拆解

P1 · 07

任务完成耗时

TIME SAVED / TURNS TO COMPLETION
M-07

任务完成耗时（时间节省率）

Task Completion Time · Time Saved
目的PURPOSE
回答「AI 是否真的省了时间」。孤立讨论耗时无意义——必须对比传统基线。这是「AI 是否创造真实价值」的第一道财务检验。
公式FORMULA
时间节省率=基线耗时 − AI 辅助耗时基线耗时× 100%
口径：AI 辅助耗时 = 生成等待 + 提示撰写 + 核验 + 返工。漏掉核验与返工是最常见的自欺。
评估标准THRESHOLDS
≥ 40% 显著15–40% 有效< 15% 存疑
低于 15% 时应追问：这个场景是否根本不该用 AI，而应改用辅助模式。
数据来源DATA
  • 行为时间戳（开始 / 提交 / 验收全链路）
  • 基线数据库：同类任务的历史完成时间
  • 用户自查记录（核验时段标记）
分层SEGMENTS
按任务类型、复杂度、用户熟练度切分。新手的时间节省常被学习成本吃掉，需单独观察爬坡曲线。
触发TRIGGER
⚡某类任务节省率 < 15% → 触发「该场景是否值得用 AI」评审，评估改交互模式或下线入口
闭环CLOSED LOOP
耗时拆解定位瓶颈（等待 / 提示 / 核验哪段最长）→ 对症提速（流式输出 / 并行工具 / 预取 / 模板化提示）→ 重测 → 沉淀：新基线写入基线库，提速手段入效能模式库。
M-08

用户监督负担

User Supervision Burden
目的PURPOSE
回答「用户是否仍需盯着 AI」。Agent 价值的试金石：如果名义上自主执行、实际上全程盯梢，工作只是从「做」变成了「监工」——Agent 就没有兑现承诺。
公式FORMULA
监督时间占比=监督时间（盯进度 / 查状态 / 等确认）任务总时长× 100%
辅助指标：每任务进度查看次数、空闲等待中的主动刷新次数。
评估标准THRESHOLDS
< 20% 健康20–40% 预警> 40% 危险
长任务（> 30 分钟）单独设线：> 30% 即预警。
数据来源DATA
  • 页面焦点与停留日志
  • 进度页 / 状态页访问事件
  • 用户调研校准（区分「必要确认」与「不放心」）
分层SEGMENTS
按任务时长、自主等级、用户角色切分。长任务是重点：监督负担与任务时长呈超线性增长。
触发TRIGGER
⚡长任务监督占比 > 40% → 触发主动通知机制优化（关键节点推送 / 异常才打扰）
闭环CLOSED LOOP
高监督样本分析 → 找出用户缺什么信息（进度 / 中间产物 / 风险预警）→ 增加主动汇报点 → 验证监督占比下降 → 沉淀：「何时汇报、汇报什么」的沟通策略规范。
M-09

信任校准度

Trust Calibration
目的PURPOSE
回答「用户是否知道何时该信、何时该查」。过度信任导致事故，信任不足导致价值浪费——两个方向都是体验负债，理想状态是用户信任水平与 AI 实际可靠性对齐。
公式FORMULA
校准偏离度=| 实际采纳率 − 应采纳率（按输出正确性） |应采纳率× 100%
口径：采纳行为来自日志，应采纳率由输出的客观正确性回溯判定；辅以信任量表抽样校准。
评估标准THRESHOLDS
< 15% 校准15–30% 轻度失调> 30% 严重失调
必须标注失调方向：过度信任（采纳了不该采纳的）比信任不足更危险，优先处理。
数据来源DATA
  • 采纳 / 拒绝 / 修改行为日志
  • 对应输出的客观正确性回溯
  • 信任量表（定期抽样）
分层SEGMENTS
按任务风险、有无不确定性提示、用户经验切分。高风险场景的过度信任是独立观察项，不与低风险混算。
触发TRIGGER
⚡高风险场景过度信任率 > 10% → 触发不确定性表达强化（风险标注 / 置信度展示）
⚡低风险场景信任不足 → 触发可信证据展示（历史正确率 / 依据来源）
闭环CLOSED LOOP
失调样本分析 → 判断缺哪种校准信号 → 增加相应设计（不确定性标注 / 证据链 / 一致性历史）→ 验证采纳合理性改善 → 沉淀：不确定性表达规范与风险分级展示标准。
M-10

认知负担

Cognitive Load
目的PURPOSE
回答「用 AI 是否增加了脑力劳动」。省了时间但费了脑，体验仍是亏的——时间账上的收益不能掩盖认知账上的亏损。对生产力 Agent，这本账比满意度更关键。
公式FORMULA
认知负荷分=任务后微调研评分（1–5，简化 NASA-TLX）5
行为代理指标交叉验证：反复查看帮助、重复同类操作、中途长时间停顿的频次。
评估标准THRESHOLDS
≤ 3.0 健康3.0–4.0 预警> 4.0 危险
数据来源DATA
  • 任务后微 Survey（一题式，嵌入任务完成页）
  • 行为代理日志（停顿 / 回看 / 重复操作）
  • 深访（每月抽样，校准问卷偏差）
分层SEGMENTS
按界面复杂度、任务并行度、新手 / 专家切分。新手负荷高是正常的，但要观察其下降斜率——斜率平缓说明学习设计失败。
触发TRIGGER
⚡新功能发布后负荷分上升 > 0.5 → 触发交互复杂度评审，评估功能收纳入口
闭环CLOSED LOOP
高负荷环节定位（问卷开放题 + 行为回放）→ 简化界面 / 减少需记忆状态 / 增加默认值 → A/B 验证负荷分 → 沉淀：复杂度预算写入设计规范，新功能上线前强制评估。
M-11

首次交付通过率

First-pass Acceptance Rate
目的PURPOSE
回答「是否减少了返工」。衡量「第一次就把事做对」的能力——它同时反映理解质量与交付质量，是效率与质量的交汇点。
公式FORMULA
首次通过率=首次交付即通过验收的任务数总交付任务数× 100%
口径：交付后 24h 内未收到修改请求且被使用，视为通过。
评估标准THRESHOLDS
≥ 75% 健康60–75% 预警< 60% 危险
数据来源DATA
  • 验收记录与修改请求日志
  • 返工工单（关联原因分类）
  • 交付物使用追踪
分层SEGMENTS
按交付类型、任务复杂度、验收方切分。不同验收人严格度不同，需校准后比较。
触发TRIGGER
⚡某类任务通过率低于同类基线 15pp → 触发该类交付模板 / 流程 / 质检专项
闭环CLOSED LOOP
未通过原因三分类（理解偏差 / 质量不足 / 标准不清）→ 对症下药（强化澄清 / 交付前自检 / 标准前置到任务开始时）→ 验证 → 沉淀：交付 checklist 与验收标准库更新。
M-12

持续使用率

Retention Rate
目的PURPOSE
回答「用户是否愿意再次使用」。前面所有指标的最后投票：留存是体验的总账。但要看「委托深度留存」——用户回来了，且把更重要的事交给了它，才叫真留存。
公式FORMULA
留存率=窗口期内再次使用的用户数上窗口使用用户数× 100%
口径：按周 / 月双窗口观察；「使用」定义为发起过至少一次任务委托，而非仅打开产品。
评估标准THRESHOLDS
无普适阈值——建立自身趋势线，重点监测环比变化与分层结构。留存结构比绝对值更有信息量：高价值场景留存是否在涨？
数据来源DATA
  • 活跃与任务委托日志
  • 委托风险等级变迁记录（深度留存判定）
  • 流失用户访谈
分层SEGMENTS
按生命周期（新 / 成长 / 成熟）、首次体验成败（首任务成败对次周留存影响巨大）、使用场景切分。
触发TRIGGER
⚡次周留存环比降 > 5pp → 触发流失归因专项，反查同期体验指标异动
闭环CLOSED LOOP
流失用户分层访谈 → 与体验指标交叉定位短板（哪个维度先把用户推走的）→ 修复 → 验证回流 → 沉淀：留存归因模型更新，「首任务成功」等关键旅程进入新用户保障机制。

CHAPTER 05 · OPERATING RHYTHM

循环如何进入组织日常

拆解卡定义了单指标的自循环，组织的节奏让 12 张卡咬合成一台机器。四个节拍，频率递减、深度递增：

DAILY · 每日
测量与值守

仪表盘自动运行，触发规则值守。红线类（安全违规）实时告警；P0 指标异动当日进队列。人不看数，机器找人。

WEEKLY · 每周
触发与诊断

触发项进入体验例会，用分层视图做归因：定位是哪个维度、哪类任务、哪类用户的问题。产出诊断结论与改进工单。

BI-WEEKLY · 双周
改进与验证

改进项以 A/B 或灰度上线，对照指标验证因果。验证周期内冻结相关改动的叠加，保证归因干净。

MONTHLY · 每月
固化与进化

验证有效的改进沉淀为资产：评测用例、设计规范、验收标准、阈值修订。同时复盘指标体系本身——失效的指标下线。

关键在于沉淀的强制力：每一条验证有效的改进，必须回答「它变成了什么资产」才能关单。没有沉淀的改进是一次性的，有沉淀的改进才让下一圈循环站在更高的起点上——这就是「自进化」与「反复救火」的分界线。

从 12 张卡到完整指标字典

本卷拆解了 12 个核心指标。原体系还有 50+ 指标，不必一次拆完——按三批推进，让拆解节奏跟上循环的消化能力：

三批推广路线
ROLLOUT IN 3 WAVES
壹
第一批 · P0 深拆（本卷已完成）

六张 P0 卡直接投入运转，跑通「触发 → 诊断 → 沉淀」的第一个完整循环。用真实循环的反馈反过来修订卡片模板。

贰
第二批 · 六维全量覆盖

每个体验维度补拆 2–3 个代表性指标（如意图漂移率、委托成功率、执行进度可见性、NPS），使每个维度至少有一张「能触发、能闭环」的活指标。

叁

CODA · 结语

指标体系的价值，不在于表格的完备，而在于每一行数字都连着一次触发、一次诊断、一次改进和一笔沉淀。当 12 张卡在组织的四个节拍里持续运转，体验就不再靠灵感与救火前进，而是沿着「测量 → 触发 → 诊断 → 改进 → 验证 → 固化」的轨道——每一圈，都比上一圈更懂你的用户。这，就是指标对体验自进化的意义。
