四类证据 · 五张标准表 · 三层版本 · 一座飞轮 4 EVIDENCE × 5 TABLES × 3 VERSIONS × 3 LOOPS

CHAPTER 01 · ACQUISITION

四类证据怎么获取

VOL.01「如何真正测量」给出四类证据的定义与内容清单；本节把它们工程化：每类证据一个采集方案——用什么手段采、核心事件是什么、走什么工具链、要防什么质量风险。采集纪律先行于技术选型：埋点命名全局唯一、属性 schema 冻结后才允许上线、任何采集变更走发布流程。

EVIDENCE 01
行为数据BEHAVIORAL LOGS

原文锚：任务完成、重试、纠错、中断、接管、放弃、重复使用。

采集手段
双端埋点：客户端 SDK 记交互流（点击 / 输入 / 停留 / 焦点），服务端任务编排层记状态机终态；两侧以 session_id + task_id 关联。
核心事件
task_start / clarify_round / regenerate / correction / tool_call / error / task_end（终态枚举：completed · failed · abandoned · taken_over）。
工具链
埋点 SDK → 消息队列 → 原始层落库（T+0）；全量采集、只注册不改义，指标在下游定义。
质量风险
事件丢失、属性缺失、重复上报——以 event_id 幂等键去重；降级补传机制保完整性。
EVIDENCE 02
客观评测OBJECTIVE BENCHMARKS

原文锚：标准任务集、正确性测试、约束检查、工具执行结果、专家审核。

采集手段
评测平台对版本化的标准任务集定期跑批 + 线上失败样本沉淀回用例库 + LLM-as-judge 初筛 + 人工评审终审。
关键口径
验收标准与 rubric 事前定义；判分人一致性抽检（Kappa ≥ 0.75）；评测环境与线上环境隔离，防数据串味。
工具链
用例库（PR 评审合入）→ 跑批调度 → 判分流水 → fact_eval。
质量风险
评测集过拟合（只修用例不改产品）与判分漂移（模型换代后 rubric 语义偏移）——rubric 必须随模型版本登记。
EVIDENCE 03
主观研究SUBJECTIVE RESEARCH

原文锚：满意度、信任、可控性、认知负担、访谈与可用性测试。

采集手段
任务后一题式微调研（嵌入完成页，频控防疲劳）+ 周期量表（信任 / 可控性，月度）+ NPS（季度）+ 深访与可用性测试（月度抽样）。
关键纪律
每份问卷锚定 task_id，可与行为数据 join；开放题编码进结构化字段；防时机污染——刚失败的任务不弹满意题。
工具链
微调研组件 → fact_survey；访谈录音 → 转写编码 → 用户研究档案。
质量风险
幸存者偏差（流失用户答不到题）与社会期许偏差——问卷只做假设不做结论，与行为数据交叉校准。
EVIDENCE 04
真实业务结果BUSINESS OUTCOMES

原文锚：节省的时间、交付质量、返工成本、风险事件和长期价值。

采集手段
业务系统对接——工单系统（返工工单）、交付验收系统（通过记录）、财务（成本核算）、增长平台（留存转化），以 task_id 为贯通键。
关键纪律
任务 ID 必须写进业务单据——归因断链是本类数据的第一死因；月度对账：业务侧记录与 fact_task 的匹配率。
工具链
系统间 ETL / webhooks → fact_business → 月度对账报告。
质量风险
归因断链与口径不一（「返工」在业务系统与 AI 侧定义不同）——口径映射表登记在案，随对账更新。
采集总纪律：四类证据共用一套关联键（user_id · session_id · task_id）。任何一张表缺键，指标就只剩孤证——VOL.01 的立场是「四类证据互相印证」，印证的前提是能连上。

CHAPTER 02 · STANDARDIZATION

清洗、标准化与五张标准表

原始数据不能直接喂指标。参照数仓分层惯例，建 BRONZE → SILVER → GOLD 三层管道：原始层保真、清洗层治理、指标层定口径。口径唯一出口在 gold 层——看板、告警、回归对比都只读 gold，任何人不许在查询里临时改公式。

BRONZE · 原始层
原样落库，不可变
  1. 只追加不修改——保留原始证据链，清洗错了可以随时回放
  2. 按天分区，保留 13 个月滚动归档
  3. 四类证据分管道进入：行为流水 / 评测流水 / 问卷原始表 / 业务快照
SILVER · 清洗层
五步治理，坏数据不静默
  1. 幂等去重：以 event_id / record_id 去重，重复上报只计一次
  2. 时区统一：全部归一为业务时区（UTC+8），时间戳带源时区留档
  3. 会话切分与任务归因：多条事件归并为一任务一行，切分规则版本化
  4. PII 脱敏：goal_text 等自由文本哈希化或移入安全区，分析区不见明文
  5. schema 校验：缺属性、类型错的数据进死信队列，人工裁决
GOLD · 指标层
口径唯一出口
  1. 指标宽表：按 71 卡口径计算物化视图，公式即 SQL 的唯一权威
  2. 周快照：snapshot_id 标识，看板与告警只读快照，保证同图同数
  3. 回归对比：口径变更后新旧快照可并排复算，支撑双轨期

五张标准表 SCHEMA v1.3 · SILVER LAYER

四类证据 + 任务主表，构成指标消费的最小完备集。fact_task 是主表：一任务一行，其余四张表都以 task_id 挂靠。每张表的字段变更走第四章的版本流程。

拆解字典 71 卡每张都有「公式」与「数据来源」行——本章把两者接到五张表上。下面 15 个代表指标覆盖六卷，每个公式的分子分母都能指到具体字段；其余指标同法映射，口径以卡片为准。消费纪律：指标只在 gold 层计算，公式变更走口径版本流程（见第四章）。

CHAPTER 04 · VERSIONING

数据的版本管理

数据会变，口径会变，评测集也会变。没有版本管理的数据，历史不可比、回溯不可行、责任不可查。版本管理分三层：表结构版本、评测集版本、指标口径版本——三者各有变更纪律，共用一张登记表。

V-01

schema 版本 · 表结构

DATA SCHEMA当前 v1.3
纪律
只加不删不改：新列向后兼容（历史行记 NULL）；字段更名与类型变更视为破坏性变更，升级大版本 v2——新旧 schema 双写迁移一个季度，验证后停旧。
回溯
每行数据带 data_ver，记录生成它的清洗规则版本；清洗规则修复时可按版本重刷 silver / gold 层，bronze 永不动。
V-02

评测集版本 · 用例库

EVAL SET当前 v2.1
纪律
用例入库走 PR 评审合入，版本号 +1；rubric（判分标准）与评测集同版本号联动，模型换代时 rubric 重新校准并登记。
回溯
评测集升级后全量回归重跑，新旧版本分数双轨记录——字典卡的阈值基线必须标注「基于 eval_set vX」，跨版本比分数是自欺。
V-03

口径版本 · 指标公式

METRIC DEFINITION当前 v1.0
纪律
与拆解字典卡片脚注的「口径版本 v1.0 / 2026-10」同一套账。公式变更必须登记变更日志：改了什么、为什么改、影响哪些卡、谁批准。
回溯
口径纠错 → 历史重算（一次到位）；口径演进 → 新老口径双轨并行一个观察期（通常四周），趋势确认后切换，旧口径存档只读。

CHAPTER 05 · THE FLYWHEEL

数据正向飞轮：成立，但要三道担保

回到这个问题本身：「依赖这些数据进行根因分析优化后又产生新的数据」——这可以叫数据正向飞轮吗？可以，但「正向」不是自动的，需要三道担保：

其一，正向 = 每转一圈资产增厚——失败样本沉淀为评测用例（评测集变强）、根因归档为知识（归因变快）、盲区转化为新埋点（视野变全）。这是 AI 产品区别于传统 BI 的独特环节：数据不只是用来「看」的，是用来「喂」的。其二，每个环节都有制度依赖——PR 评审、归因例会、埋点变更流程，缺一项飞轮就打滑。其三，它会退化——三种反模式让它空转甚至倒转，见本章末。

内圈 · 评测飞轮：样本沉淀让指标更准 中圈 · 归因飞轮：优化验证让产品变好 外圈 · 口径进化圈：盲区转化让视野变全

飞轮的六个环节对应本方案前四章：采集（一章四卡）→ 标准化（二章三层管道）→ 消费（三章指标映射）→ 诊断（字典「触发机制」+ 闭环手册归因）→ 优化（字典「改进闭环」）→ 沉淀（失败样本入用例库、归因入知识库、盲区转新埋点）——然后新行为产生新数据，回到采集。沉淀环节（金色）是飞轮区别于普通闭环的关键：没有它，回路只是重复；有了它，回路是复利。

飞轮转速 FLYWHEEL VELOCITY · 飞轮自身也要被度量

三种退化反模式 ANTIPATTERNS · 飞轮空转的防线

埋点腐化INSTRUMENTATION ROT

症状：schema 漂移无人认领、事件悄悄改名、属性大面积缺失。

后果：数据质量滑坡 → 指标失真 → 所有下游决策建立在坏数据上。

对策：埋点变更走发布流程 + 死信队列日清 + 埋点覆盖率纳入飞轮转速月报。
评测过拟合BENCHMARK OVERFIT

症状：评测分数持续上涨，线上指标不动；团队只在用例上「改进」。

后果：指标好看、体验没变——评测集失去对真实世界的代表性。

对策：用例只进真实失败样本 + 保留 20% 新鲜用例防陈旧 + 评测分与线上指标背离即触发审计。
只算不归因DASHBOARD THEATER

症状：看板越做越精美，但从没有人因为指标异动开过归因会。

后果：飞轮断在「诊断」环节——有测量无改进，数据变成装修。

对策：每个指标必须挂字典卡的触发机制与改进闭环——没有闭环的指标不予立项。
