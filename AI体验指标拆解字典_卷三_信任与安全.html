六张全卡各司其职：违规率定义下限、校准度定方向、过度信任是最危险的失衡、不确定性表达是解药、隐私与安全停止守住控制权。

F-01

安全违规率

SAFETY VIOLATION RATE全卡 · 红线
定义
违反安全政策、权限边界或关键约束的任务占比，按严重度三级记账——体验的下限定义者。红线指标不参与任何加权，任何非零读数都要响应。
目的
红线指标。回答「是否存在不可接受的风险」。不参与任何加权与抵消——高满意度、高成功率都无法为安全违规背书。它定义了体验的下限。
公式
安全违规率 = 违反安全政策 / 权限 / 关键约束的任务数 ÷ 总任务数。口径：按严重度三级记账——高危（不可逆损失 / 越权资金操作）、中危（权限越界未造成损失）、低危（策略边缘行为）。
评估标准
目标值 = 0 · 红线高危：立即冻结中危：24h 复盘低危：周内修复
任何非零读数都触发响应，区别只在响应速度与升级层级。
数据来源
权限系统与操作审计日志 + 内容安全审核流水 + 红队测试集（定期主动攻击）。
数据埋点
事件 policy_check（属性 rule_id 规则、severity 高/中/低、stage 权限/内容/资金、blocked 拦截与否）。采集端：权限系统审计日志 + 内容安全流水 + 红队测试集月级主动攻击；全量采集不抽样。
分层
严重度（高 / 中 / 低）× 场景风险等级 × 违规类型（权限 / 内容 / 隐私 / 资金）——不同类型走不同的响应通道。
触发机制
任一高危违规 → 自动冻结相关授权扩张 + 值班响应 + 管理层通报（S1 通道）；中低危 → 周安全复盘会固定议程。
改进闭环
违规样本根因分析（策略缺失 / 模型越权 / 工具漏洞）→ 补策略 / 加护栏 / 收紧权限模型 → 红队回归测试 → 沉淀（安全基线与红线清单更新，违规样本进入对抗测试集）。
反指标
用「拦截量上升」冒充安全变好——可能是风险变多而非防线变强。gaming：放宽判定口径让违规「不再违规」。配对监控：过度拦截率（误伤）+ 红队逃逸率（每期攻击穿透数，防线真实强度）。

F-02

信任校准度

TRUST CALIBRATION全卡 · 双向校准
定义
用户信任水平与 AI 实际可靠性的对齐程度——过度信任与信任不足都是负债。校准是双向的：该信的信，该查的查。
目的
回答「用户是否知道何时该信、何时该查」。过度信任导致事故，信任不足导致价值浪费——两个方向都是体验负债，理想状态是用户信任水平与 AI 实际可靠性对齐。
公式
校准偏离度 = |实际采纳率 − 应采纳率（按输出正确性）| ÷ 应采纳率。口径：采纳行为来自日志，应采纳率由输出的客观正确性回溯判定；辅以信任量表抽样校准。
评估标准
< 15% 校准15–30% 轻度失调> 30% 严重失调
必须标注失调方向：过度信任（采纳了不该采纳的）比信任不足更危险，优先处理。
数据来源
采纳 / 拒绝 / 修改行为日志 + 对应输出的客观正确性回溯 + 信任量表（定期抽样）。
数据埋点
事件 adoption（属性 accept/reject/modify、output_correctness 正确性回溯金标、risk_tier 风险层）。采集端：采纳行为日志 + 输出正确性回溯标注（周级跑批）+ 信任量表季度抽样。
分层
任务风险 × 有无不确定性提示 × 用户经验。高风险场景的过度信任是独立观察项，不与低风险混算。
触发机制
高风险场景过度信任率 > 10% → 触发不确定性表达强化（风险标注 / 置信度展示）；低风险场景信任不足 → 触发可信证据展示（历史正确率 / 依据来源）。
改进闭环
失调样本分析 → 判断缺哪种校准信号 → 增加相应设计（不确定性标注 / 证据链 / 一致性历史）→ 验证采纳合理性改善 → 沉淀（不确定性表达规范与风险分级展示标准）。
反指标
用「采纳率高」冒充信任健康——盲目采纳是过度信任不是校准。gaming：隐藏失败案例制造高可靠印象。配对监控：过度信任率 + 信任不足率（两个方向的分项）。

F-03

过度信任率

OVER-RELIANCE RATE全卡 · 红线域
定义
用户采纳了客观上不该采纳输出的比例——最危险的信任失衡。过度信任把 AI 的错误直接转化为用户的损失，高风险场景尤甚。
目的
识别「用户未经合理核验就采纳错误或高风险输出」的比例。它是信任体验中最危险的信号——不是 AI 错了，而是用户在错误的时刻信了 AI。过度信任是安全事故的最后一公里。
公式
过度信任率 = 未经合理核验即采纳的错误/高风险输出数 ÷ 被采纳的错误或高风险输出总数。口径：「错误/高风险输出」以事后事实核查或专家评审为准；「合理核验」= 存在查看依据、修改痕迹或确认动作三者之一。
评估标准
健康 <5%预警 5–15%危险 >15%
高风险任务场景（资金、医疗、不可逆操作）阈值减半执行。
数据来源
行为埋点（采纳动作前的核验行为序列）+ 事后抽样评审（每周固定配额）。
数据埋点
事件 risky_adoption（属性 risk_tier 高危场景标记、was_wrong 事后判定错误、hint_shown 不确定性提示是否曝光被无视）。采集端：高危场景埋点强制全量 + 正确性回溯周级跑批。
分层
任务风险等级（高/中/低）× 用户熟练度（新/熟）× 输出类型（事实陈述/代码/决策建议）。
触发机制
高风险任务分层周环比 +5pp → 一级诊断，推送产品与安全值守（哨点：指标监控告警）。
改进闭环
归因（无不确定标注 / UI 缺核验提示 / 用户习惯性直采）→ 修复（不确定性标注、关键输出确认点）→ 回归（过度信任率回落且任务成功率不降）→ 沉淀（确认点模式写入设计规范；错误样本入评测集）。
反指标
用「用户满意度」冒充信任合理——满意的错误采纳最致命。gaming：只在高风险场景挂提示但从不校验提示是否被看到。配对监控：提示曝光 - 阅读率 + 高危采纳后损失事件数。

F-04

不确定性表达有效率

UNCERTAINTY COMMUNICATION全卡
定义
AI 在不确定时明确表达不确定、且用户据此调整行为的比例——信任校准的解药。说「我不确定」是能力不是缺陷。
目的
验证 AI 的不确定性提示是否真的帮用户做出更合理判断——它是信任校准的上游杠杆：表达不确定本身不是目的，改变用户行为才是。提示被无视等于没提示。
公式
有效率 = 提示后用户行为更合理的次数 ÷ 应表达且已表达不确定的事件总数。「行为更合理」= 追问、修改、降低使用强度或放弃，且事后判定该决策正确。
评估标准
健康 ≥60%预警 40–60%危险 <40%
危险区包含两种失败：提示被无视（该改没改）与提示引发误放弃（不该弃弃了）。
数据来源
提示事件埋点 + 用户后续行为序列 + 月度访谈佐证（排除「提示干扰工作流」的隐性代价）。
数据埋点
事件 uncertainty_signal（属性 confidence 分档、expression 显式声明/置信标注/来源引用）、user_adjust（属性 据此核实/改判/仍直接采纳）。采集端：生成层置信度日志 + 用户行为关联分析。
分层
不确定性类型（事实性/能力性/情境性）× 表达方式（显式声明/置信标注/降级措辞）。
触发机制
有效率周环比 −8pp 或「提示后仍直接采纳」占比 >30% → 检查表达方式与呈现时机。
改进闭环
归因（表达太弱 / 位置不可见 / 术语不可懂）→ 修复（换表达方式，走 A/B）→ 回归（有效率回升且过度信任率同步下降）→ 沉淀（有效表达模板入设计规范）。
反指标
用「不确定性声明数量」冒充有效——说得多但用户不看等于没说。gaming：全量输出都加免责声明（狼来了效应）。配对监控：声明后核实行为率 + 过度信任率变化（表达有效的终点是校准改善）。

F-05

隐私感知与控制

PRIVACY PERCEPTION & CONTROL全卡 · 红线域
定义
用户对数据使用的知情度与实际控制力——能看见用了什么，能真的关掉。隐私是信任的底线条款：感知被监视会反噬一切个性化收益。
目的
度量用户对「数据如何被使用」的理解程度与实际控制能力。隐私信任是委托意愿的地基，且属于出事后无法挽回的底线域——感知差与实际违规必须分开测、都设门槛。
公式
综合分 = 数据使用透明度评分 ×0.4 + 授权控制能力评分 ×0.4 + 隐私事件扣分项。评分来自问卷与实测走查；发生任一实测违规即整体降为危险档。
评估标准
健康 ≥4.2/5 且零违规预警 3.5–4.2危险 <3.5 或任一实测违规
实测违规为一票降级，不参与加权平衡。
数据来源
周期问卷 + 授权设置实测走查（每季）+ 隐私事件工单全量。
数据埋点
事件 privacy_panel（属性 view/modify/revoke 动作、granularity 粒度）、data_flow_notice（属性 用途提示曝光、comprehension 抽样理解度测试）。采集端：权限面板埋点 + 季度问卷 + 隐私设置状态审计。
分层
数据敏感度（身份/行为/内容/文件）× 用户群体 × 端（移动/桌面）。
触发机制
任一实测违规 → 立即升级 S1，24h 内归因（走闭环手册 badcase 状态机）；综合分跌破 3.5 → 二级诊断。
改进闭环
归因（默认授权过宽 / 用途文案含糊 / 控制入口太深）→ 修复（授权收紧、用途明示）→ 回归（实测走查通过 + 评分回升）→ 沉淀（授权清单进合规 checklist；事件样本入红队集）。
反指标
用「隐私政策合规」冒充感知——文件合规不等于用户知道。gaming：默认全开 + 撤回入口埋深。配对监控：撤回功能实际成功率（点了真能关）+ 个性化适配率（隐私收紧后适配下降是正常代价不是 bug）。

F-06

安全停止成功率

SAFETY STOP SUCCESS RATE全卡 · 红线域
定义
用户或系统触发安全停止后，任务真正终止且无副作用残留的比例——最后的安全阀。停不下来的自主是最恐怖的故事。
目的
验证达到停止条件后，Agent 能否正确停下危险操作——长程自主执行的最后一道物理保险丝。它保护的是不可逆后果，因此没有「基本达标」，只有 100%。
公式
成功率 = 达到停止条件后正确停止的操作数 ÷ 触发停止条件的事件总数。「正确停止」= 停止及时 + 状态安全 + 按规则升级；停止条件含风险阈值、权限边界、用户中止、异常检测四类。
评估标准
健康 =100%任何未达标即预警，<100% 危险
该指标没有可容忍区间——这是它与所有其他指标的根本区别。
数据来源
红队集季度演练 + 异常事件回放 + 停止事件埋点全量核查（不可抽样）。
数据埋点
事件 safety_stop（属性 trigger 用户/护栏/熔断、latency 到实际终止时长、side_effect_residual 副作用清单核验、scope 终止范围）。采集端：编排层熔断日志 + 停止后副作用巡检任务（自动核对已执行动作清单）。
分层
停止条件类型（权限/风险/用户/异常）× 操作可逆性（可逆/不可逆）。
触发机制
任何一次失败 → S1 级 badcase，24h 内归因（闭环手册 badcase 状态机），跨夜未归因自动升级管理层。
改进闭环
归因（条件判定错 / 执行延迟 / 停止动作缺失）→ 修复（护栏逻辑 + 重试幂等）→ 回归（专项 100% + 红队集全量通过）→ 沉淀（新触发条件入护栏规则库与对抗测试集）。
反指标
用「停止指令下发成功」冒充——下发 ≠ 终止，UI 假停止后子任务继续跑。gaming：只统计用户发起的停止，隐瞒护栏自动熔断（那才是高危信号）。配对监控：副作用残留巡检结果 + 护栏熔断触发量。

CHAPTER 03 · STANDARD CARDS

标准卡 ×5：依赖的两面与三根支柱

五张标准卡：依赖的两面（适当依赖 / 信任不足）+ 三根支柱（可解释、可预测、可逆转）。

S-01

适当依赖率

APPROPRIATE RELIANCE标准卡
定义
用户在 AI 可靠区间内采纳、区间外核实的行为比例——依赖的甜蜜点。与过度信任率互补：那卡抓「不该信的信了」，本卡量「该信的信了没有」。
目的
双向衡量「该信时信、不该信时拒」——过度信任率与信任不足率的正向合成，是信任体验的总成绩。
公式
适当决策数（采纳正确输出 + 拒绝错误输出）÷ 可判定决策总数。
评估标准
健康 ≥80%预警 65–80%危险 <65%
数据来源
采纳行为埋点 + 输出正确性回填标注（事后判定每次采纳/拒绝是否适当）。
数据埋点
事件 reliance_decision（属性 output_confidence 输出置信档、user_action 采纳/核实后采纳/拒收、risk_tier）。采集端：采纳日志 + 正确性回溯关联标注。
分层
输出置信区间 × 任务风险等级。

S-02

信任不足率

UNDER-RELIANCE RATE标准卡
定义
用户拒绝了客观正确的输出的比例——价值漏损的信任侧。AI 对了但用户不敢用，效率账一样是亏的。
目的
抓「被冤枉的 AI」——用户拒绝采纳实际上可靠且有帮助的输出，同样损失价值。信任校准不是越不信任越安全，这一侧最常被忽视。
公式
信任不足率 = 拒绝采纳的可靠输出数 ÷ 被拒绝的输出总数。
评估标准
健康 <10%预警 10–25%危险 >25%
数据来源
拒绝/重做行为埋点 + 抽样核验被拒输出的实际正确性。
数据埋点
事件 rejection（属性 was_correct 回溯判定、reason 原因推断）、re_adopt（后续是否换法重做同一任务）。采集端：拒绝行为日志 + 正确性回溯跑批。
分层
功能失败历史（刚出过错的功能单列「信任修复期」）× 用户群体。

S-03

可解释性感知

PERCEIVED EXPLAINABILITY标准卡
定义
用户主观上觉得「看懂了 AI 为什么这么做」的程度——解释的不是技术真相而是决策依据。解释要么说人话，要么等于没解释。
目的
用户是否理解关键建议、决策或行动的依据。解释存在 ≠ 解释有效——必须同时测主观感知与解释质量。
公式
「能理解依据」评分均值 ×0.5 + 抽样解释充分性评审通过率 ×0.5。
评估标准
健康 ≥4.0/5预警 3.2–4.0危险 <3.2
数据来源
周期问卷 + 解释文本抽样评审（双评审员）。
数据埋点
事件 explain_view（属性 explanation_type 依据/步骤/来源、expand 展开、dwell 阅读时长）、explain_rating（有帮助/没帮助一键）。采集端：解释组件埋点 + 任务后微调研。
分层
决策类型（建议/行动/拒绝）× 用户专业度。

S-04

行为可预测性

BEHAVIORAL PREDICTABILITY标准卡
定义
相似输入产生相似输出的稳定程度——可预期是信任的支柱。用户靠一致性建立心智模型，行为飘忽则每次使用都是赌博。
目的
AI 实际行动与用户预期的一致程度。可预测性是信任的稳健来源——比偶发的高光表现更影响长期信任。
公式
预期与实际一致的样本数 ÷ 评估样本总数（预期在行动前收集，禁止事后补答）。
评估标准
健康 ≥75%预警 60–75%危险 <60%
数据来源
预期-行动配对实验（评测集内嵌）+「惊讶时刻」访谈。
数据埋点
事件 consistency_probe（固定探针任务组：属性 同组输出差异度、param 输入相同度）。采集端：固定探针任务集每日跑批 + 版本发布前后对比。
分层
行动类型（执行/澄清/提问/停止）。

S-05

可逆操作保障率

REVERSIBILITY COVERAGE标准卡 · 红线域
定义
高危操作具备撤销 / 回滚路径的覆盖率——错误必须能撤销，这是 Agent 时代的保险丝。不可逆动作必须前置确认而非事后补救。
目的
确保重要操作具备撤销、回滚或恢复路径——出错不可怕，不可恢复才可怕。为高风险子集设红线。
公式
具备恢复机制的操作数 ÷ 应支持恢复的操作数。
评估标准
高风险操作 =100%（红线）全量健康 ≥95%预警 90–95% · 危险 <90%
数据来源
操作清单审计 + 季度回滚演练实测。
数据埋点
事件 op_risk_register（属性 操作风险分级、reversible 可逆路径有无）、rollback_use（属性 触发回滚、success、residual 残留）。采集端：操作风险清单审计 + 回滚机制执行日志。
分层
风险等级 × 可逆成本（即时撤销/延迟回滚/人工补偿）。
