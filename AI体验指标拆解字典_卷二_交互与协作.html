CHAPTER 02 · FULL CARDS

全卡 ×4：七维完整拆解

四张全卡各守一面：纠错看可控、耗时看真实价值、延迟看效率第一因、澄清负担看表达成本。

F-01

用户纠错成功率

USER CORRECTION SUCCESS RATE全卡
定义
用户发出修正意图后达到预期结果的比例——可控性的核心观测。「AI 会犯错不可怕，用户纠不动才可怕」：纠错是用户最后的方向盘。
目的
回答「用户能否有效纠正 AI」。可控性体验的核心：AI 会犯错不可怕，用户纠不动才可怕——「失控感」正是用户不敢委托的根源。
公式
纠错成功率 = 纠正后达到预期结果的次数 ÷ 有效纠错尝试总次数。口径：「有效纠错尝试」= 用户发出明确修正意图的动作（重新生成 / 补充说明 / 否定反馈 / 手动接管）。
评估标准
≥ 80% 健康65–80% 预警< 65% 危险
低于 65% 意味着用户「说了也没用」——是流失的最强前导信号之一。
数据来源
纠错动作日志（类型 / 轮次 / 内容）+ 纠错后的任务终态追踪 + 否定反馈按钮与重生成事件。
数据埋点
事件 correction_attempt（属性 type 重试/补充说明/否定反馈/接管、seq_no 会话内第几次、target 被纠对象）、correction_result（属性 success、latency 到生效轮次、escalated 升级人工）。采集端：客户端动作埋点 + 任务终态关联。
分层
纠错类型（重试 / 补充说明 / 接管 / 放弃）× 纠错轮次。连续纠错 3 轮以上的会话单列——它们是挫败感的重灾区。
触发机制
同一会话同类纠错连续失败 2 次 → 触发升级人工通道 / 换策略建议；整体跌破健康线 → 触发纠错交互（反馈控件 / 修正表达方式）优化专项。
改进闭环
失败纠错样本 → 诊断纠错接口缺失（用户无法精准表达哪里错）→ 增加针对性反馈控件 / 修正建议 → 验证成功率 → 沉淀（高频纠错模式入库，反哺默认行为设计）。
反指标
用「反馈按钮点击量」冒充纠错成功——点了不等于改好了。gaming：把纠错入口做浅诱导点击刷量。配对监控：纠错后 3 轮放弃率（纠了更糟的信号）+ 连续失败升级率（纠不动流向人工的比例）。

F-02

任务完成耗时

TASK COMPLETION TIME · TIME SAVED全卡
定义
从任务发起到验收的全链路净耗时，与传统基线对比得出的节省——价值的第一道财务检验。含等待、撰写、核验、返工四段，漏任何一段都是自欺。
目的
回答「AI 是否真的省了时间」。孤立讨论耗时无意义——必须对比传统基线。这是「AI 是否创造真实价值」的第一道财务检验。
公式
时间节省率 = (基线耗时 − AI 辅助耗时) ÷ 基线耗时。口径：AI 辅助耗时 = 生成等待 + 提示撰写 + 核验 + 返工。漏掉核验与返工是最常见的自欺。
评估标准
≥ 40% 显著15–40% 有效< 15% 存疑
低于 15% 时应追问：这个场景是否根本不该用 AI，而应改用辅助模式。
数据来源
行为时间戳（开始 / 提交 / 验收全链路）+ 基线数据库（同类任务的历史完成时间）+ 用户自查记录（核验时段标记）。
数据埋点
事件 task_timer（属性 phase 等待/输入/核验/返工各段时长、baseline_id 匹配基线）。采集端：客户端时间戳全链路 + 基线库匹配服务；核验时长用焦点 + 停留推断并抽样校准。
分层
任务类型 × 复杂度 × 用户熟练度。新手的时间节省常被学习成本吃掉，需单独观察爬坡曲线。
触发机制
某类任务节省率 < 15% → 触发「该场景是否值得用 AI」评审，评估改交互模式或下线入口。
改进闭环
耗时拆解定位瓶颈（等待 / 提示 / 核验哪段最长）→ 对症提速（流式输出 / 并行工具 / 预取 / 模板化提示）→ 重测 → 沉淀（新基线写入基线库，提速手段入效能模式库）。
反指标
用「AI 生成时长」冒充任务耗时——机器快不等于人省时。gaming：不计返工段，或把基线取最慢样本。配对监控：返工率（耗时省了返工爆了 = 假节省）+ 核验时长占比（省时转移到核验 = 左手倒右手）。

F-03

响应延迟

RESPONSE LATENCY全卡 · 效率第一因
定义
从用户动作到系统开始有效响应的时长分布（P50 / P95）——效率体验的第一因。可感知延迟由「首 token 时间」主导，而非总完成时间。
目的
所有效率指标的技术第一因。用户对速度的感知是非线性的：首字延迟决定「它在动吗」的活着感，总时长决定「值得等吗」的成本判断。Agent 时代延迟结构变了——思考-工具-再思考的长执行里，感知延迟设计（进度可见性）与真实延迟同等重要。
公式
双口径：首字延迟 P50 / P95（提交到首个反馈出现）与 任务总时长 P50 / P95。三段拆解：模型延迟 / 工具延迟 / 渲染延迟；等待中有有效进度展示的时长按折扣计入感知等待。
评估标准
首字 P95 ≤2s预警 2–5s危险 >5s
任务总时长按难度分档定基线，禁止跨档比较。
数据来源
客户端埋点全量 + 三段拆解日志（每段独立计时）。
数据埋点
事件 latency_trace（属性 t_first_token 首包、t_first_meaningful 首个有效内容、t_complete 完成、mode 流式/非流式、tool_calls 链路工具数）。采集端：客户端 SDK 打点 + 服务端链路追踪；按交互类型（聊天 / 工具调用 / 长任务启动）分开建分位。
分层
交互类型（首答 / 追问 / 工具执行段）× 任务难度分档 × 端（移动 / 桌面）。
触发机制
P95 周环比 +30% → 一级诊断；「长时间无反馈」类 badcase ≥5 例/周 → 检查进度可见性而非只压延迟。
改进闭环
归因（模型慢 / 工具慢 / 流水线串行）→ 修复（并行化、流式输出、预取）→ 回归（P95 回落且进度可见性不降）→ 沉淀（延迟预算表入技术规范；无反馈模式入评测集）。
反指标
用「平均延迟」冒充体验——长尾（P95）才是用户流失点。gaming：先返回占位文案压低首响指标（假流式）。配对监控：交付质量（快而糙）+ 占位响应后续修正率（假流式识别器）。

F-04

澄清负担

CLARIFICATION BURDEN全卡
定义
用户为让 AI 理解任务而付出的额外表达成本——被追问次数、重复说明时长、补充信息体量。与需求澄清有效率对偶：那边看追问值不值，这边看用户付了多少。
目的
用户为补充信息、解释需求付出的轮次或时间。澄清本身不是坏事——必要的澄清是任务成功的前提；本指标量的是「无效澄清」：AI 该懂没懂造成的重复解释。
公式
澄清负担 = 无效澄清轮次（或时长）÷ 总任务数。无效澄清三类：同一信息用户重复提供 / 澄清后 AI 行为未改变 / 澄清内容本可从上下文推断。
评估标准
健康 <0.5 轮/任务预警 0.5–1.0危险 >1.0
数据来源
会话轮次标注（重复表达模式自动识别）+ 人工抽检校准。
数据埋点
事件 clarify_cost（属性 ask_count 被追问次数、restate_chars 重复说明字数、duration 追问环节耗时）。采集端：会话层自动统计 + 会话后微调研交叉校准（区分「必要澄清」与「没听懂」）。
分层
澄清类型（上下文 / 偏好 / 文件 / 术语）× 用户熟练度。
触发机制
环比 +0.2 轮 → 优先检查上下文保持率（卷一 F-03）与意图理解——澄清负担升高多数是记忆与理解的下游症状。
改进闭环
归因（上下文丢失 / 意图理解错 / 默认值缺失）→ 修复 → 回归（负担回落且需求澄清有效率不降——别把必要澄清也优化没了）→ 沉淀（「本可推断」样本入评测集；主动澄清策略入规范）。
反指标
用「零澄清」冒充低负担——不问可能是硬猜，代价后置到返工。配对监控：目标对齐率（不问但对齐才是真省）+ 返工原因中「理解偏差」占比（负担后置的证据）。

CHAPTER 03 · STANDARD CARDS

标准卡 ×5：协作的五个把手

五张标准卡是协作的五个把手：轮次、表达、控制、多模态通道、关键节点确认。

S-01

任务完成轮次

TURNS TO COMPLETION标准卡
定义
从任务发起到完成的人机往返轮次——交互成本的粗计量。轮次本身无善恶：必要确认算协作，无效往返才是损耗，需与澄清 / 纠错事件交叉定性。
目的
从开始到完成任务的平均交互轮数——效率的轮次账。但轮次少不等于体验好：复杂任务的必要确认与澄清不该被省掉。
公式
有效轮次（剔除必要确认与澄清轮）÷ 完成任务数，与总轮次双轨记录——差值即「必要交互密度」。
评估标准
比任务类型基线 −10%±10%+10%
以任务类型基线为锚，不做绝对阈值。
数据来源
会话埋点 + 轮次性质标注（必要 / 无效）。
数据埋点
事件 turn_log（属性 turn_count 总轮次、turn_type 正常/澄清/纠错/重试、resolution_turn 终轮）。采集端：会话层自动累计；轮次类型由事件关联打标。
分层
任务类型 × 必要交互密度。
来源警示：交互次数少，不一定代表体验好。复杂任务可能需要必要的确认和澄清——更合理的目标是减少无效交互，而不是消灭所有交互。

S-02

指令可表达性

PROMPT EXPRESSIBILITY标准卡
定义
用户能用自然语言准确下达意图的难易程度——表达门槛。表达不出的需求等于不存在；本卡衡量「说得清」的成本，是澄清负担的上游。
目的
用户能否用自然、简洁的表达获得目标结果——表达门槛就是使用门槛，「prompt 功力」不应该成为产品的前置要求。
公式
用 ≤N 轮自然表达达成目标的任务比例（N 按任务类型定）；辅以 prompt 重写频率（用户推翻自己措辞重来的次数）。
评估标准
健康 ≥80%预警 65–80%危险 <65%
数据来源
任务集评测（普通人措辞样本，不用工程师措辞）+ prompt 重写埋点。
数据埋点
事件 prompt_edit（属性 edits_before_send 发送前改写次数、delete_ratio 删改比）、input_duration（属性 首条指令撰写时长）。采集端：输入框埋点 + 标准任务集的口头表达用户测试（抽样）。
分层
用户专业度 × 任务复杂度。

S-03

操作可控性

CONTROLLABILITY标准卡
定义
用户对执行过程的实际控制力——停、改、回、接管四类操作可发现、可触达且真实生效的比例。可控性是信任的操作面：说得出，且说了真的算数。
目的
用户能否有效改变 AI 的方向、范围、参数和结果——可控性是信任的操作面：说得出「停、改、回」，且说了真的生效。
公式
被正确执行的控制动作数 ÷ 此类动作总数（方向 / 范围 / 参数 / 结果四类）。
评估标准
健康 ≥90%预警 80–90%危险 <80%
数据来源
控制动作埋点 + 评测集控制场景跑批。
数据埋点
事件 control_action（属性 op 停止/修改/回滚/接管、reachable 入口触达、executed 生效确认、latency 到生效时长）。采集端：控制控件埋点 + 操作结果状态机核对。
分层
控制类型（方向 / 范围 / 参数 / 结果）× 时机（执行前 / 中 / 后）。

S-04

多模态交互成功率

MULTIMODAL INTERACTION SUCCESS标准卡
定义
语音、图片、文件等非文本通道完成交互的成功率——通道可用性。通道多样化扩大入口，但每个通道失败都是体验断点。
目的
通过文本、语音、图片、文件等方式成功完成的任务比例——多模态不是展示功能，是降低表达成本的通道；失败的多模态反而增加负担（说了三遍没听懂的语音）。
公式
该模态完成任务数 ÷ 该模态发起任务数（按模态分列，禁止混算）。
评估标准
主模态 ≥85%新模态 ≥70%
新模态上线 90 天内用放宽阈值，之后并轨。
数据来源
模态埋点 + 模态任务评测集。
数据埋点
事件 multimodal_input（属性 modality 语音/图像/文件、asr_ocr_conf 识别置信度、fallback 降级文本重试）、multimodal_result（属性 success、retry_count）。采集端：各通道 SDK 埋点 + 降级路径追踪。
分层
模态 × 任务类型 × 环境（嘈杂 / 移动 / 桌面）。

S-05

关键节点确认率

CRITICAL CONFIRMATION COVERAGE标准卡
定义
高风险动作前系统主动请求确认、且用户在知情下确认的覆盖率——授权节奏。该停的地方停了没有，比事事都问更重要。
目的
需要确认的关键操作是否真的设置了确认机制——「形式审批按钮」不算数，确认点必须在正确的位置、以正确的方式生效。
公式
正确设置确认机制的关键操作数 ÷ 应设确认的关键操作总数（正确 = 时机在前 + 内容具体 + 默认不通过）。
评估标准
高风险 =100%全量健康 ≥90%预警 <90%
数据来源
流程审计 + 确认事件埋点交叉验证。
数据埋点
事件 confirm_request（属性 node 风险节点、risk_level、context_shown 展示了什么依据）、confirm_result（属性 approve/reject/timeout、time_to_decide 决策时长）。采集端：编排层风险节点埋点 + 确认弹窗事件。
分层
操作风险等级 × 任务类型。

简卡 ×4：三要素速览

四张简卡对应协作的四个瞬间：第一印象（首次交互）、总账（协作效率）、急刹车（中断响应）、监督有效性。

L-01

首次交互成功率

FIRST-INTERACTION SUCCESS简卡
目的
首轮交互即达成预定目标的会话比例——第一印象的效率账，决定用户对「值不值得继续」的初始判断。
公式与阈值
首轮达标会话数 ÷ 总会话数　
健康 ≥60%预警 45–60%危险 <45%
按任务难度分档判级。

L-02

协作效率

COLLABORATION EFFICIENCY简卡
目的
达成目标所需的人机总时间 / 轮数 / 操作成本——效率的总账：把 AI 时间与人的时间合并计算。单看 AI 快不快、或单看人省没省，都会骗人。
公式与阈值
人机总成本 ÷ 传统基线成本　
健康 ≤0.7预警 0.7–1.0危险 >1.0
<1 即 AI 辅助仍占优。

L-03

中断响应率

INTERRUPTION RESPONSIVENESS简卡
目的
用户喊停时 AI 是否真的停——控制感的最低要求，也是用户敢委托的心理前提。
公式与阈值
被正确执行的中断指令数 ÷ 中断指令总数　
健康 ≥95%预警 85–95%危险 <85%
不可逆操作场景 = 100% 红线。

L-04

人类监督有效性

HUMAN SUPERVISION EFFECTIVENESS简卡
目的
用户是否有足够的信息、时间和权限发现并阻止错误——监督的存在不等于监督有效，形式上的审批界面不产生真实监督。
公式与阈值
具备有效监督条件的任务数 ÷ 应监督任务数（信息充分 × 时机可行 × 权限足够，三者同时满足才计 1）　
高风险任务 =100%全量健康 ≥90%

CODA · 本卷要点

好的协作像好的舞伴：你进它退，你停它止，你错它兜。交互体验的全部秘密在于让用户始终握有方向盘——表达有门、纠错有效、中断有应、监督有据。减少的是无效交互，保留的是必要确认，这才是效率与控制之间的平衡点。
