CHAPTER 02 · FULL CARDS

全卡 ×7：七维完整拆解

七张全卡即因果链本体：负荷在前、放弃 / 挫败是警号、满意度 / 复用 / NPS是回声、持续使用率是总账。

F-01

认知负担

COGNITIVE LOAD全卡
定义
使用 AI 附加的脑力劳动量——省了时间但费了脑，体验仍是亏的。对生产力 Agent，这本账比满意度更关键。
目的
回答「用 AI 是否增加了脑力劳动」。省了时间但费了脑，体验仍是亏的——时间账上的收益不能掩盖认知账上的亏损。对生产力 Agent，这本账比满意度更关键。
公式
认知负荷分 = 任务后微调研评分（1–5，简化 NASA-TLX）。行为代理指标交叉验证：反复查看帮助、重复同类操作、中途长时间停顿的频次。
评估标准
≤ 3.0 健康3.0–4.0 预警> 4.0 危险
数据来源
任务后微 Survey（一题式，嵌入任务完成页）+ 行为代理日志（停顿 / 回看 / 重复操作）+ 深访（每月抽样，校准问卷偏差）。
数据埋点
事件 post_task_survey（一题式 1–5 简化 NASA-TLX，嵌入任务完成页）、behavior_proxy（属性 帮助回看次数、重复操作、长停顿）。采集端：完成页微调研 + 行为代理日志 + 月度深访校准。
分层
界面复杂度 × 任务并行度 × 新手 / 专家。新手负荷高是正常的，但要观察其下降斜率——斜率平缓说明学习设计失败。
触发机制
新功能发布后负荷分上升 > 0.5 → 触发交互复杂度评审，评估功能收纳入口。
改进闭环
高负荷环节定位（问卷开放题 + 行为回放）→ 简化界面 / 减少需记忆状态 / 增加默认值 → A/B 验证负荷分 → 沉淀（复杂度预算写入设计规范，新功能上线前强制评估）。
反指标
用「功能数量」冒充能力——功能越多负荷越重。gaming：把负荷问卷藏在三级页面降回复率。配对监控：问卷回复率（< 30% 数据失效）+ 学习曲线斜率。

F-02

持续使用率

RETENTION RATE全卡 · 总账
定义
窗口期内再次使用的用户占比——体验的总账。要看委托深度留存：回来了且把更重要的事交出去，才叫真留存。
目的
回答「用户是否愿意再次使用」。前面所有指标的最后投票：留存是体验的总账。但要看「委托深度留存」——用户回来了，且把更重要的事交给了它，才叫真留存。
公式
留存率 = 窗口期内再次使用的用户数 ÷ 上窗口使用用户数。口径：按周 / 月双窗口观察；「使用」定义为发起过至少一次任务委托，而非仅打开产品。
评估标准
无普适阈值——建立自身趋势线，重点监测环比变化与分层结构。留存结构比绝对值更有信息量：高价值场景留存是否在涨？
数据来源
活跃与任务委托日志 + 委托风险等级变迁记录（深度留存判定）+ 流失用户访谈。
数据埋点
事件 session_return（周 / 月双窗口，属性 task_delegated 是否真委托、risk_tier 迁移）、churn_followup（流失访谈）。采集端：活跃日志 + 委托风险等级变迁追踪。
分层
生命周期（新 / 成长 / 成熟）× 首次体验成败（首任务成败对次周留存影响巨大）× 使用场景。
触发机制
次周留存环比降 > 5pp → 触发流失归因专项，反查同期体验指标异动。
改进闭环
流失用户分层访谈 → 与体验指标交叉定位短板（哪个维度先把用户推走的）→ 修复 → 验证回流 → 沉淀（留存归因模型更新，「首任务成功」等关键旅程进入新用户保障机制）。
反指标
用「打开次数」冒充留存——打开没用成是虚假活跃。gaming：用 push 拉回计数。配对监控：委托深度迁移率 + 首任务成功率（首战败的留存坍塌）。

F-03

总体满意度

CSAT全卡 · 温度计
定义
用户对体验的综合评价（CSAT）——温度计：能快速反映冷暖，但只能确认问题、不能定位问题。
目的
用户对本次交互或任务体验的评分——最经典也最易被误用的指标。本卷立场：满意度是体验的「事后温度计」而非「方向盘」——它能确认问题存在，不能定位问题在哪；且信任不等于满意度：用户可能喜欢表达风格，却不该据此信任它做高风险决策。
公式
CSAT = 满意（4–5 分）用户数 ÷ 回收评分总数。口径：任务级即时评分与周期性总体评分分开记录；回收率 <20% 时警惕自选择偏差（不满者更愿意评价）。
评估标准
健康 ≥4.2预警 3.5–4.2危险 <3.5
回收率与评分趋势必须联检——高分低回收可能是沉默的流失。
数据来源
任务后即时评分 + 周期问卷；抽样主动邀评修正自选择偏差。
数据埋点
事件 csat_survey（属性 score、task_context 触发场景、verbatim 开放文本）、sampling_rule 场景分层抽样。采集端：任务完成后随机触发（同用户频控防疲劳）。
分层
任务类型 × 风险等级 × 用户阶段。
触发机制
周环比 −0.2 → 先查行为指标（本卷放弃率 F-04、挫败率 F-05）是否先行恶化——行为先于评分，直接从 CSAT 开题会慢两拍。
改进闭环
归因（用行为指标定位环节）→ 修复 → 回归（CSAT 回升且行为指标同步——防止只把评分「运营」上去）→ 沉淀（满意度-行为归因映射表）。
反指标
用「满意度均值」冒充健康——均值掩盖两极。gaming：只在成功任务后弹问卷。配对监控：评分方差 + 差评场景归因率。

F-04

任务放弃率

ABANDONMENT RATE全卡
定义
用户中途放弃任务的比例——体验崩溃的即时信号。放弃是最诚实的一票：不满意到懒得反馈。
目的
用户未完成任务便结束交互的比例——效率与认知失败的最响亮投票。每一次放弃背后，都是某项成本超过了当时的收益预期。它是用脚投票，比任何问卷都诚实。
公式
放弃率 = 未完成任务便结束交互的会话数 ÷ 总会话数。口径区分：合理放弃（目标已达成 / 用户主动改向）不计入；挫败放弃（含重试、负反馈或高操作密度后退出）单独标记。
评估标准
健康 <8%预警 8–15%危险 >15%
必须按任务难度分档判级——难任务天然放弃率高。
数据来源
会话行为埋点 + 放弃会话抽样归因（回访 / 访谈补足行为数据看不到的动机）。
数据埋点
事件 abandon（属性 abandon_step 放弃环节、last_action 放弃前最后动作、recovery 之后是否换路重试）。采集端：会话状态机 + 放弃后挽留弹层（可选、克制）。
分层
放弃时机（首轮 / 中途 / 交付前）× 任务类型 × 用户熟练度。
触发机制
周环比 +3pp 或「交付前放弃」占比上升 → 一级诊断。交付前放弃是最痛的丢失——成本已付，价值未取。
改进闭环
归因（延迟 / 澄清循环 / 错误未恢复 / 价值不符）→ 修复 → 回归（放弃率回落且任务成功率不降——防止把用户劝回去硬扛）→ 沉淀（放弃模式入评测集；归因结论入知识库）。
反指标
用「会话时长长」冒充粘性——磨蹭到放弃的会话很长。gaming：把放弃后 24h 内回归算未放弃。配对监控：挫败率（上游）+ 放弃点聚类（哪个环节劝退）。

F-05

挫败率

FRUSTRATION RATE全卡
定义
用户表现出挫败信号（重复纠错、愤怒表达、暴力操作、立即放弃）的任务占比——情绪面的领先指标，领先于满意度下滑与流失。
目的
用户表现出明显挫败或放弃意图的会话比例——流失的领先指标：挫败先于放弃，放弃先于流失。它让团队在 NPS 掉下来之前就看到问题在哪。
公式
挫败率 = 检出挫败信号的会话数 ÷ 总会话数。信号五类：负面表达（词表 / 模型识别）、高频重试、负反馈点击、异常高操作密度、中途放弃。
评估标准
健康 <5%预警 5–10%危险 >10%
数据来源
会话文本信号检测（自动）+ 周度人工抽检校准检出器精度。
数据埋点
事件 frustration_signal（属性 type 连续纠错≥3轮/负面情绪词/快速重复点击/秒退、intensity 强度、downstream 放弃或差评）。采集端：行为模式检测 + 文本情绪分类；规则透明可解释。
分层
挫败触发点（错误 / 延迟 / 被误解 / 循环）× 用户类型。
触发机制
环比 +2pp；单一触发点占比 >40% → 该触发点立专项（挫败原因集中说明是系统性问题而非用户差异）。
改进闭环
归因 → 修复 → 回归（挫败率回落且检出器精度保持——防「信号消失是因为检测退化」）→ 沉淀（新挫败模式入信号词表；触发点模式入巡检清单）。
反指标
用「差评率」冒充挫败——挫败的人多数不评分，直接走。gaming：隐藏负面反馈入口让信号消失。配对监控：任务放弃率（下游）+ 纠错连续失败率。

F-06

主动复用率

REPEAT TASK USAGE全卡
定义
用户在无提示下再次为同类任务选择 AI 的比例——用脚投票的信任。区别于留存（还在用）：复用是「为这件事，还是选它」。
目的
用户再次将同类任务委托给 AI 的比例——行为化的价值投票：说过满意不代表会再来，再来才是真认可。它是留存的质量版：持续使用率（VOL.04）只看「回来没有」，本指标看「回来做正事没有」。
公式
复用率 = 再次委托同类任务的用户数 ÷ 完成过该类任务的基数。口径：「主动」= 用户自发发起，排除系统引导触发的重复；同类任务按任务类型聚类。
评估标准
健康 ≥40%预警 25–40%危险 <25%
按任务类型分档——高频任务类天然更高，禁止跨类比较。
数据来源
行为埋点（任务类型序列分析，全量）。
数据埋点
事件 repeat_choice（属性 task_type 同类任务、entry 无推荐位/无 push 自发进入、interval 间隔）。采集端：入口来源标记（自发 vs 引导）。
分层
任务类型 × 委托间隔（次日 / 周内 / 月内）× 用户阶段（首次复用 / 稳定复用）。
触发机制
核心任务类环比 −5pp → 检查该类任务近期成功率与交付质量——复用下滑是质量问题的滞后回声。
改进闭环
归因（上次体验差 / 价值不符 / 替代方案分流）→ 修复 → 回归（复用回升且成功率稳定）→ 沉淀（任务类-复用基线表；流失归因入知识库）。
反指标
用「使用频次」冒充复用——频次可能是惯性而非选择。配对监控：入口来源占比 + 同类任务委托成功率（复用的底气）。

F-07

推荐意愿

NPS全卡 · 滞后指标
定义
用户向他人推荐的可能性（NPS）——滞后指标与口碑资产。纪律：只能确认问题、不能定位问题。
目的
用户推荐产品给他人的意愿评分——增长的口头代理指标。用法纪律：NPS 是滞后的合成结果，只能用来确认与汇报，不能用来定位；且 AI 产品存在「好用但说不出口」的推荐歧义——用户难以向朋友解释 AI 产品的价值。
公式
NPS = 推荐者%（9–10 分）− 贬损者%（0–6 分）。口径：季度频率足够；必须追问开放题「为什么」并归类编码——没有归因的分数变化只是噪音。
评估标准
健康 ≥30预警 0–30危险 <0
分值变化 ±5 以内视为波动，不做过度解读。
数据来源
季度问卷 + 开放题归类编码（双人编码校验）。
数据埋点
事件 nps_survey（属性 score、verbatim、segment 生命周期）+ 推荐行为追踪（分享 / 邀请）。采集端：季度脉搏调研（频控严格）+ 行为数据关联。
分层
用户阶段 × 使用强度 × 获客渠道。
触发机制
跌破 0 或单季 −10 → 全面诊断——从行为指标倒查，禁止直接从 NPS 分数开题。
改进闭环
归因（开放题编码 × 行为指标交叉验证）→ 修复 → 回归（下季 NPS 回升且编码主因消失）→ 沉淀（贬损主因 Top5 表；归因映射入知识库）。
反指标
用「NPS 单值」冒充关系健康——要看分布与变化率，且滞后于体验半年。gaming：在满意度最高峰时点触发调研。配对监控：挫败率（领先信号）+ 推荐实际转化（说了是否真推荐）。

标准卡 ×3：负荷、学习与情绪价值

三张标准卡：心智负担（负荷的过程版，与全卡认知负担一静一动互为印证）、易用性感知（学习成本）、情绪改善幅度（情绪价值账）。

S-01

心智负担

MENTAL WORKLOAD标准卡
定义
用户需要记住、理解、操心的信息量——「用 AI 还要记着替 AI 记」是典型病灶。与认知负担分工：认知看任务全程脑力，心智看记忆与追踪压力。
目的
使用 AI 时的主观工作负荷（NASA-TLX 等量表）——认知负担的过程版：认知负担（本卷 F-01）看「理解监督核验」的总努力，心智负担看执行中的即时负荷；一静一动互为印证。
公式
NASA-TLX 六维加权分（任务结束后即时填写，0–100 标准化）。
评估标准
健康 ≤45预警 45–60危险 >60
数据来源
月度抽样任务后即时量表 + 任务回放访谈。
数据埋点
事件 memory_demand（属性 需用户重复提供的信息次数、状态回查次数）+ 周期微调研。采集端：会话层信息重复检测 + 调研校准。
分层
任务类型 × 交互模式（监督型 / 委托型）。

S-02

易用性感知

PERCEIVED EASE OF USE标准卡
定义
用户主观感到「容易上手、不费劲」的程度——上手门槛的感知面。感知易用性决定尝试意愿，实际易用性决定留下。
目的
用户认为学习和使用 AI 的难易程度——学习成本的主观面，直接决定新用户的第一个月留存。
公式
问卷均值（易学 / 易用 / 无需教程三题）×0.6 + 新用户首周关键动作完成率 ×0.4（主观感知 × 客观行为合成）。
评估标准
健康 ≥4.0预警 3.2–4.0危险 <3.2
数据来源
周期问卷 + 新用户行为漏斗。
数据埋点
事件 ease_survey（属性 分值、新手/专家分层）、onboarding_funnel（首用漏斗各步骤流失）。采集端：周期调研 + 新手漏斗埋点。
分层
用户阶段（首周 / 首月 / 成熟）× 功能域。

S-03

情绪改善幅度

EMOTIONAL IMPROVEMENT标准卡
定义
任务前后用户情绪状态的正向变化——AI 帮完忙，人是更轻松了还是更烦了。情绪是关系的记忆底色。
目的
交互前后用户自评情绪状态的变化——AI 的情绪价值账：陪伴、教育类产品的核心指标；生产力产品可作辅助信号。
公式
交互后自评 − 交互前自评（单题 1–10 或 PANAS 简表；会话级配对采样，低打扰非强制）。
评估标准
健康 +0.5 以上预警 0 – +0.5危险 负值
负值 = AI 让用户情绪变差，是净伤害。
数据来源
会话前后配对自评 + 抽样访谈。
数据埋点
事件 mood_pair（任务前 / 后各一题情绪自评，属性 delta 变化、task_valence 任务性质）。采集端：轻量前后测（低频抽样防打扰）。
分层
场景类型（陪伴 / 教育 / 生产力）× 用户状态。
来源警示：情绪指标不可被「讨好评」优化——情绪改善必须与依赖质量联检，高分低依赖的讨好型交互是虚假繁荣。
