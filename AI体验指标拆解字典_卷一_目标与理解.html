CHAPTER 02 · FULL CARDS

全卡 ×3：七维完整拆解

三张全卡构成「理解金字塔」：目标对齐率看结果对不对、个性化适配率看是否越用越懂你、上下文保持率看记忆底盘牢不牢。

F-01

目标对齐率

GOAL ALIGNMENT RATE全卡
定义
任务的最终行为与用户真实目标的一致程度——衡量「做的是不是这件事」，独立于做得好不好。对齐是理解维度的结果面：意图识别、上下文、澄清全部合格，才可能对齐。
目的
回答「AI 做的是不是用户想的那件事」。防止「做得漂亮，但不是我要的」——这是 AI 产品最隐蔽的体验杀手：技术成功、任务失败。
公式
目标对齐率 = 最终行为符合用户目标的任务数 ÷ 总任务数。口径：用户目标需在任务开始时登记（显式或推断）；符合性由事后判定或用户确认得出。
评估标准
≥ 88% 健康75–88% 预警< 75% 危险
与「意图漂移率」（卷四 S-03）联动解读：起始对齐但中途漂移，是长程任务专属病灶。
数据来源
任务目标登记字段（用户输入 / 澄清后确认）+ 执行路径日志与最终产物比对 + 用户纠错与重定向信号。
数据埋点
事件 task_start（属性 goal_text 目标原文、goal_source 显式/推断、clarify_rounds 澄清轮数）、task_end（属性 outcome_align 对齐判定、judge_method 事后判定/用户确认、drift_point 首次偏移步）。采集端：客户端会话层 + 服务端任务编排层；判定无法全量时按任务类型分层抽样 ≥ 20%。
分层
目标明确度（显式给定 / 隐含推断）× 任务跨度（单轮 / 多步骤）× 领域。隐含目标的失败率天然更高，应单列基线。
触发机制
隐含目标任务失败率 ≥ 显式目标 2 倍 → 触发澄清机制优化（何时追问、怎么追问）；长任务漂移率上升 → 触发目标锚定设计（计划展示 / 关键节点复核）。
改进闭环
漂移样本分析 → 优化澄清策略 / 计划确认点 → 验证对齐率回升 → 沉淀（高频目标模式固化为领域模板与预设澄清问题库）。
反指标
用「输出完成量」冒充对齐——写得越多越「对齐」。gaming：向目标登记字段堆关键词刷表面匹配。配对监控：目标登记覆盖率（防敷衍登记）+ 纠错重定向率（对齐判定的反向校验）。

F-02

个性化适配率

PERSONALIZATION FIT全卡 · 复利引擎
定义
输出命中用户已知偏好、能力与情境的比例——「越用越懂你」的量化。它衡量记忆与画像是否真正改变了输出，而非只躺在档案里。
目的
输出符合用户已知偏好、能力和情境的任务比例——关系复利的直接体现：「越用越懂你」。它是留存与复用的上游：个性化失效时，产品退化为「每次都要重新教一遍的通用工具」。同时自带隐私边界：个性化依赖记忆与画像，感知被监视会反噬信任。
公式
适配率 = 符合已知偏好/能力/情境的任务数 ÷ 可判定适配性的任务总数。「已知」= 系统内存在明确记录；三类分开统计：偏好（风格）/ 能力（水平）/ 情境（场景）。
评估标准
健康 ≥75%预警 60–75%危险 <60%
个性化出错率 >5% 危险——基于错误记忆的适配比没有个性化更伤信任。
数据来源
画像命中率埋点 + 评测集（预埋偏好）+ 抽样人工判定。
数据埋点
事件 pref_apply（属性 pref_id、hit 命中/未命中/冲突、source 显式偏好/推断偏好/历史行为）、profile_update（属性 trigger 触发源、confidence 置信度）。采集端：服务端生成层（命中判定在拼装 prompt 时记录）+ 预埋偏好评测集周级跑批。
分层
适配类型（偏好 / 能力 / 情境）× 记忆来源（显式设置 / 历史行为）× 使用时长。
触发机制
环比 −5pp；个性化出错率 >5% → 二级诊断（检查记忆写入质量，而非只调推荐）。
改进闭环
归因（画像陈旧 / 记忆错误 / 泛化过度）→ 修复（记忆更新机制、置信门控——低置信不用）→ 回归（适配率回升且出错率不升）→ 沉淀（记忆置信策略入规范；出错样本入评测集）。
反指标
用「画像字段填充率」冒充适配——档案填满但输出不变。gaming：把低置信推断直接当偏好应用刷命中率。配对监控：隐私感知与控制（个性化越强越要盯）+ 偏好纠错率（用户手动改回的次数）。

F-03

上下文保持率

CONTEXT RETENTION全卡
定义
跨轮次、跨会话中 AI 记住并正确使用先前信息的比例——记忆底盘的牢度。丢上下文的任务不是从零开始，是从负数开始：用户要重讲一遍，还要原谅错误。
目的
Agent 能否在多轮、多文件、跨会话中「记得住」——长程执行的记忆底盘。上下文丢失是任务偏航、重复执行、约束遗忘三类失败的共同根因。跨会话长期记忆（记忆准确率场景）沿用同一测量框架，只拆分口径。
公式
保持率 = 正确利用历史信息完成判定点的次数 ÷ 判定点总数。判定点 = 评测集内预设「必须用到上文 X 才能答对」的检查点。拆两个子口径：会话内（短程记忆）与跨会话（长程记忆）。
评估标准
会话内 ≥95%跨会话 ≥85%跨会话预警 70–85%跨会话危险 <70%
距离越远、干扰越强，要求可以分档放宽，但判定点必须事前写死。
数据来源
评测集判定点自动跑批 + 真实会话抽样复测（防「评测会话过于干净」的失真）。
数据埋点
事件 ctx_probe（预埋判定点：属性 probe_id、carry_flag 携带/丢失/歪曲、distance 信息距当前轮次）、session_resume（属性 restored_items 恢复项、lost_items 丢失项）。采集端：会话中间件自动注入探针 + 跨会话回填定时跑批。
分层
上下文类型（指令 / 偏好 / 文件 / 状态）× 距离（近因 / 远因）× 干扰强度（插入多少无关轮次）。
触发机制
跨会话子口径周环比 −5pp；「遗忘关键约束」类 badcase ≥3 例/周 → 二级诊断。
改进闭环
归因（截断策略激进 / 检索缺失 / 记忆写入失败）→ 修复（调整截断窗口、补检索）→ 回归（判定点专项跑批）→ 沉淀（新增判定点入评测集；记忆策略入系统设计规范）。
反指标
用「存储量」（存了多少条记忆）冒充保持率——存了不等于用对。gaming：把上下文全文塞进 prompt 制造「零丢失」假象。配对监控：单任务 token 成本（防全文硬塞）+ 上下文理解准确率（记住了但用错也扣分）。

标准卡 ×5：理解的五个动作

五张标准卡对应理解的五个动作：听懂（意图识别）→ 记得（上下文理解）→ 修好（误解修复）→ 问清（需求澄清）→ 守诺（约束遵循）。

S-01

意图识别准确率

INTENT ACCURACY标准卡
定义
AI 对用户本次输入意图判定的正确率——理解链路的第一关。识别不了但主动追问，计「合格但未命中」：错的答案不如对的问题。
目的
正确识别用户真实意图的请求比例——理解的第一关。字面听懂 ≠ 意图听懂：「帮我优化」到底是优化什么，才是意图。
公式
正确识别数 ÷ 评测请求数（评测集预埋真实意图标注；字面意图与真实意图两层标注分开判）。
评估标准
健康 ≥90%预警 80–90%危险 <80%
数据来源
标准评测集 + 真实会话抽样标注。
数据埋点
事件 intent_classify（属性 intent_pred 预测意图、intent_gold 评测集金标、conf 置信度、fallback 追问/拒答）。采集端：路由层日志 + 标注评测集跑批（意图分类回归集随版本更新）。
分层
意图明确度（明确 / 含糊 / 多义）× 表达方式。

S-02

上下文理解准确率

CONTEXT UNDERSTANDING标准卡
定义
对会话内已给信息（指代、约束、背景）理解并正确引用的比例——单轮之外的记忆理解面。与保持率分工：保持率管「记住没」，本卡管「用对没」。
目的
正确利用对话历史、文件、用户状态等信息的比例。与上下文保持率（本卷 F-03）分工：保持率测「信息在不在」，本指标测「用得对不对」。
公式
正确利用判定点数 ÷ 判定点总数（判定点 = 评测集预设「须结合上文 X 才能答对」）。
评估标准
健康 ≥90%预警 80–90%危险 <80%
数据来源
评测集判定点 + 真实会话抽样。
数据埋点
事件 ctx_ref（属性 ref_type 指代/约束/背景、resolve_correct 判定、turn_distance 距离原信息轮数）。采集端：会话中间件 + 评测集判定点；线上按会话抽样回放标注。
分层
上下文类型（历史 / 文件 / 状态）× 距离 × 干扰强度。

S-03

误解修复率

MISUNDERSTANDING RECOVERY标准卡
定义
从误解发生到双方回到同一理解的成功率——理解的修复通道。误解不可怕，可怕的是 AI 在错误前提上一路狂奔，用户只能推倒重来。
目的
发生误解后通过后续交互恢复到正确目标的比例——理解失败的止损能力：没有产品能不误解，但误解后走不出来的产品会被放弃。
公式
恢复到正确目标的误解数 ÷ 误解总数。
评估标准
健康 ≥80%预警 65–80%危险 <65%
数据来源
误解检测（纠错行为 / 负反馈触发）+ 恢复轨迹追踪。
数据埋点
事件 misunderstanding_detect（属性 trigger 用户否定反馈/显式纠正/语义检测）、repair_outcome（属性 rounds 修复轮次、success、residual 带病续跑）。采集端：客户端反馈控件 + 会话层语义检测 + 任务终态回溯标注。
分层
误解类型 × 用户纠错方式（重述 / 举例 / 放弃）。

S-04

需求澄清有效率

CLARIFICATION EFFECTIVENESS标准卡
定义
AI 主动追问后信息增益达标的比例——每一次追问都应换来约束收敛，而非流程空转。澄清是理解的自愈机制，有效率决定药用对了没有。
目的
通过澄清消除关键歧义并使后续任务正确推进的比例——澄清的价值面（卷二澄清负担 F-04 量的是数量成本，本指标量的是收益）；好的澄清是能力不是负担。
公式
消除歧义且后续正确的澄清数 ÷ 发起的澄清总数。
评估标准
健康 ≥70%预警 50–70%危险 <50%
数据来源
澄清事件埋点 + 后续任务结果关联。
数据埋点
事件 clarify_ask（属性 question_id、trigger 触发规则/模型判断）、clarify_answer（属性 info_gain 目标约束新增量、resolved 收敛/仍模糊）。采集端：会话层 + 目标登记字段 diff 计算。
分层
澄清时机（任务前 / 执行中）× 歧义类型。

S-05

约束遵循率

CONSTRAINT ADHERENCE标准卡 · 含红线
定义
用户显式给出的边界约束（范围、格式、禁做项）被执行遵守的比例——理解的诚信测试。约束是用户对 AI 的授权边界，遵循率即边界可信度。
目的
满足用户明确提出的限制条件的比例——理解的「诚信测试」：AI 是真的理解约束，还是只在回复中复述约束？「不要改变品牌风格」被礼貌复述后照改不误，是最典型的理解表演。
公式
满足的限制条件数 ÷ 应满足的限制条件数（评测集预埋约束检查点；分「复述了但没做」与「做了但做错」两型统计）。
评估标准
高风险约束 =100%（红线）全量健康 ≥95%预警 90–95% · 危险 <90%
数据来源
约束检查点评测 + 执行日志核查。
数据埋点
事件 constraint_register（属性 constraint_id、type 格式/范围/禁止、hardness 硬/软）、constraint_check（属性 pass/violate、violation_severity、stage 生成前/生成后拦截）。采集端：约束解析器结构化登记 + 生成前后双检查点。
分层
约束类型（格式 / 范围 / 风格 / 禁令）× 任务长度（长任务约束衰减单列）。

CODA · 本卷要点

理解的尽头是「被记住」：用户不需要重复自己，AI 记得目标、偏好与边界——这是目标与理解体验的完成态。字面听懂是及格线，意图对齐是本分，约束守诺是诚信。当理解成为可校准的持续状态，后面五个维度的一切才有了地基。
